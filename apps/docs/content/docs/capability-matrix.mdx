# Capability matrix

Two pages

This reference is split in two pages to keep each one light. Part 2 continues with the later sections: [Downshift capability matrix, part 2: context and packaging](/docs/capability-matrix-part-2/).

Downshift by Tiago Vilas Boas · [https://github.com/tiagovilasboas/downshift](https://github.com/tiagovilasboas/downshift)

Audit date: 2026-10-17. Source of truth for writers: every row below was read from code, tests or a dated evidence file in this repository, not from existing marketing text. When a public doc says more than a row supports, the doc is listed in [Contradictions and overclaims found](/docs/capability-matrix-part-2/#contradictions-and-overclaims-found).

**Status vocabulary (one of five):** _Implemented_ means code, tests and at least one dated observation on a real harness. _Implemented, not validated everywhere_ means the code is shared but the effect was observed on some harnesses or plans only. _Experimental_ means shipped behind a flag or a maintainer command, with no production claim. _Planned_ means documented intent with no code path. _Not supported_ means the harness or design cannot do it.

Harness status words (Completed, Functional, Beta, Experimental) are a different scale and are defined in [harness-matrix.md](/docs/harness-matrix/#status-per-harness); they appear only in section 4.

Shorthand: `core` is `internal/core`, `cmd` is `cmd/downshift`, "matrix" is `docs/reference/harness-matrix.md`, "A/B" is `docs/evidence/subagent-routing-ab-2026-10-15.md`, "audit" is `docs/evidence/hardening-audit-2026-10-15.md`.
