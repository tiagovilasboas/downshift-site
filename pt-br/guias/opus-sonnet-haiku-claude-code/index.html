Qual modelo usar no Claude Code: Opus, Sonnet ou Haiku para cada tarefa

Downshift por Tiago Vilas Boas. Atualizado em 24 de outubro de 2026

Este Downshift é uma ferramenta em Go para agentes de código com IA, não a biblioteca React downshift de autocomplete.

Resumo

Haiku para trabalho mecânico que dá para conferir, Sonnet para correção com escopo fechado, Opus para desenho que atravessa pacotes e para tudo que encosta em autenticação, pagamento ou segredo. Pela tabela da Anthropic, o token de entrada do Opus custa 40 vezes o do Haiku. O erro mais caro é deixar todo subagente no Opus por padrão.

Opus, Sonnet e Haiku no Claude Code: qual a diferença?

O Claude Code expõe as três famílias como apelidos (aliases). A documentação de configuração de modelo descreve o opus como o Opus mais recente para raciocínio complexo, o sonnet como o Sonnet do dia a dia de código e o haiku como o modelo rápido e econômico para tarefas simples. Na API da Anthropic esses apelidos apontam para Opus 5.5, Sonnet 5.5 e Haiku 5.5; em outros provedores podem apontar para versões mais antigas.

Preços de tabela em dólar, da página de preços da Anthropic, conferidos em 2026-10-24. São preços de API: no plano Pro ou Max você gasta cota, não dólar, mas a proporção entre os modelos mostra a velocidade com que cada subagente consome essa cota. Mais do que o valor absoluto, olhe a proporção. A entrada do Opus custa o dobro da do Sonnet e 40 vezes a do Haiku em prompt curto. Subagente que lê uma árvore grande de arquivos paga quase tudo em entrada, então o modelo em que ele roda define quase toda a conta.

Qual modelo usar no Claude Code para cada tarefa?

A tabela abaixo é uma regra prática montada a partir da descrição que a própria Anthropic dá a cada apelido e da política de risco que o Downshift já traz. Não é benchmark: não tenho nota de qualidade por modelo para mostrar e não vou inventar uma.

Tipo de tarefaExemplosModeloPor quê
Edição mecânicaRenomear símbolo, corrigir typo, documentar funções, listar arquivos, ler logHaikuEscopo pequeno e resultado que teste, compilador ou grep confirmam
Correção com escopo fechadoUm teste quebrado, um bug dentro de um módulo, refatoração pequenaSonnetO padrão que a Anthropic recomenda para a maior parte do código, pela metade do preço do Opus
Desenho entre pacotesArquitetura, plano de migração, refatoração que cruza módulosOpusRaciocínio em várias etapas, em que uma escolha errada no início custa mais que os tokens
Área de riscoAutenticação, pagamento, segredos, criptografia, dados pessoais, operação destrutivaOpus ou o modelo da sessão, nunca menorUm erro sutil aqui custa muito mais do que qualquer economia de token
Pedido vago"dá uma limpada nisso", "faz aquilo"Mantenha o modelo da sessãoSem sinal claro, descer de modelo é aposta

A lógica por trás: só desça de modelo quando a tarefa for estreita e verificável ao mesmo tempo. Faltou uma das duas, fique onde está.

Haiku ou Sonnet no Claude Code: quando o mais barato dá conta?

O Haiku se paga quando quem confere o resultado não é o próprio modelo: uma suíte de testes, o type-checker, um diff que você lê em segundos. Rename, passada de comentários e inventário de arquivos entram aqui. No preço de tabela, o Sonnet custa 20 vezes o Haiku por token de entrada em prompt curto, então é nesse tipo de tarefa que a economia aparece.

Suba para o Sonnet assim que o subagente precisar escolher entre abordagens, ler código para o qual ninguém apontou ou explicar por que algo falha. Dois cuidados da página de preços: prompt do Haiku 5.5 acima de 100 mil tokens paga a faixa mais cara da tabela, e fora da API da Anthropic o apelido haiku pode cair num Haiku mais antigo, com outro preço.

Como o Claude Code escolhe o modelo do subagente?

A documentação de sub-agents define esta ordem; vale a primeira que existir:

  1. O parâmetro model que o Claude passa ao iniciar o subagente.
  2. O campo model: na definição do agente, em que inherit significa o modelo da conversa principal.
  3. A variável de ambiente CLAUDE_CODE_SUBAGENT_MODEL.
  4. O modelo da conversa principal, que é o que sobra quando nada acima está definido.
---
name: log-reader
description: Read logs and list the failing tests
model: haiku
---

Dois detalhes pegam muita gente. Sozinha, a CLAUDE_CODE_SUBAGENT_MODEL não muda os subagentes embutidos Explore e Plan; a documentação manda somar CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1 para forçar um modelo em todos. E antes da versão 2.1.251 do Claude Code a variável vinha primeiro e passava por cima do arquivo do agente, então a ordem depende da sua versão.

Por que um modelo fixo por agente não basta

Todas as opções acima escolhem um modelo para o agente inteiro. Um subagente de uso geral recebe um rename na segunda e uma migração de pagamento na terça, e a linha model: dele não distingue uma coisa da outra. O opusplan também não resolve: ele troca por modo, Opus no planejamento e Sonnet na execução, e nunca olha o que foi pedido a cada subagente.

Onde o Downshift entra

O Downshift é um hook PreToolUse local. Quando o Claude Code vai iniciar um subagente, ele lê o texto da tarefa, pontua com regras fixas e define o modelo e o esforço de raciocínio só daquela chamada. Não existe LLM no meio do caminho e o texto da tarefa nunca vai para o disco.

  • Por subagente: o rename desce, o desenho entre pacotes continua no topo.
  • Na dúvida, fica o seu modelo: se o classificador não tem confiança, o subagente roda no modelo que pediu.
  • Área de risco nunca desce: autenticação, pagamento, segredos, criptografia, dados pessoais e operação destrutiva ficam fora do modelo pequeno.

Evidência, com os limites

Bateria de quatro braços em 2026-10-21: tarefas mecânicas delegadas, 46 execuções, um operador. Contra o opusplan nativo, o roteamento gastou cerca de 24% menos tokens por tarefa aceita (intervalo de 95% de +2,1% a +46,7%) e cerca de 16% menos por execução. O braço com roteamento passou nos testes ocultos em 12 de 12 execuções. Tarefas complexas não foram medidas. Veja o método e as tabelas completas (em inglês).

Perguntas frequentes

Qual modelo o Claude Code usa por padrão?

Nos planos Pro, Max, Team, Enterprise e na API da Anthropic, o padrão aponta para o Opus 5.5, segundo a documentação de configuração de modelo conferida em 2026-10-24. Um subagente sem o campo model herda o modelo da conversa principal, a menos que CLAUDE_CODE_SUBAGENT_MODEL esteja definida.

O Haiku dá conta como subagente no Claude Code?

Para trabalho estreito e verificável, como rename, leitura de log ou listagem de arquivos, normalmente dá. Para o que exige julgamento entre vários arquivos, use Sonnet ou Opus e confira o resultado com testes, não com o resumo do próprio modelo.

O opusplan substitui escolher o modelo por tarefa?

Não. O opusplan troca por modo: Opus no modo de planejamento, Sonnet na execução. Ele não olha o que foi pedido a cada subagente.

Trocar de modelo no meio da sessão sai mais caro?

Pode sair. Cada modelo tem o próprio cache de prompt, então a troca relê a conversa sem aproveitar cache. Escolha o modelo da sessão no começo e roteie os subagentes.

Quanto o roteamento por subagente economiza?

Numa bateria em 2026-10-21 (46 execuções, um operador, tarefas mecânicas delegadas), o roteamento do Downshift gastou cerca de 24% menos tokens por tarefa aceita do que o opusplan nativo, com intervalo de 95% de +2,1% a +46,7%, e cerca de 16% menos por execução. Tarefas complexas não foram medidas.

Instale o Downshift com um comando

Pare de pagar preço de Opus em rename. Um comando instala o binário e liga o hook; rode downshift setup --dry-run antes para ver cada alteração, e downshift setup --undo restaura os backups.

curl -fsSL https://raw.githubusercontent.com/tiagovilasboas/downshift/main/install.sh | sh && downshift setup

Plugin do Claude Code

/plugin install downshift --marketplace tiagovilasboas/downshift
