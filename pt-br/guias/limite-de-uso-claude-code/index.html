O limite de uso do Claude Code acaba rápido: de onde vem o consumo

Downshift por Tiago Vilas Boas. Atualizado em 19 de outubro de 2026

Este Downshift é uma ferramenta em Go para agentes de código com IA, não a biblioteca React downshift de autocomplete.

Resumo

O limite de uso do Claude Code funciona em janelas, uma de sessão e uma semanal, e costuma acabar por contexto longo, cache frio e subagentes, não pelo número de perguntas que você fez. Este guia segue só o que a documentação da Anthropic afirma e diz o que o Downshift ainda não provou.

O limite de uso em duas janelas: sessão e semanal

Na documentação de custos, o uso de uma assinatura é contado em janelas. Para Team e Enterprise, ela descreve uma janela móvel de cinco horas e uma semanal, e a franquia de cada pessoa também é compartilhada com o chat do Claude e o Cowork. Para Pro e Max, a documentação que li não detalha esse compartilhamento, então consulte a Central de Ajuda da Anthropic, que não verifiquei.

O texto oficial está em inglês. Esta página não traz cotas em tokens, porque a documentação não as publica e eu não vou inventá-las.

O que consome mais do que parece

  • Contexto longo: o Claude Code envia a conversa inteira a cada requisição. Uma pergunta de uma linha em uma sessão aberta o dia todo consome pelo contexto acumulado.
  • Cache frio: a primeira mensagem depois de uma pausa maior que a vida útil do cache reprocessa o contexto todo. Em assinatura, a conversa principal pede cache de uma hora. Com chave de API ou provedor de nuvem, o padrão é de cinco minutos.
  • Subagentes: cada subagente, e cada agente de um workflow, envia as próprias requisições além das da conversa principal.
  • Tarefas agendadas e mensagens entre sessões: disparam com a sessão ociosa e enviam o contexto todo de novo.
  • Compactação: o /compact lê a conversa que vai resumir, então compactar um contexto grande já é uma requisição grande.

Como ler o /usage

Em planos Pro, Max, Team e Enterprise, o /usage mostra uma divisão do que conta para o limite. Ela atribui o uso recente a skills, subagentes, plugins e servidores MCP, e sinaliza comportamentos como contexto longo ou falhas de cache quando um deles passa de 10%. Os valores vêm do histórico local desta máquina, então outros dispositivos e o claude.ai não entram.

A linha Prompt cache (main), da v2.1.251 em diante, mostra o total de falhas e se o cache está quente. Ela cobre só a conversa principal, não os subagentes.

Se a divisão mostrar subagentes como grande fatia, o próximo passo é ver em que modelo eles rodam. Se mostrar falhas de cache, olhe as pausas e as trocas de modelo antes de qualquer outra mudança.

Trocar de modelo não destrava o limite geral

Segundo a documentação, as mensagens de limite de sessão e de limite semanal indicam uma janela compartilhada por todos os modelos. Por isso trocar com /model não devolve o acesso. Já depois de uma mensagem específica, como a do limite do Opus, trocar para um modelo de outra família permite continuar.

O que dá para ajustar

  • Rodar /clear entre tarefas sem relação, e compactar em pausas naturais.
  • Desativar MCPs sem uso e baixar o esforço em tarefas simples.
  • Pedir model: haiku nos subagentes que fazem trabalho simples, como a Anthropic sugere.
  • Evitar trocar de modelo no meio da tarefa, já que cada modelo tem o seu cache.
  • Mudar uma coisa por vez e rodar /usage de novo para ver o efeito.

Onde o roteamento de subagentes entra

O Downshift é um hook que escolhe o modelo de cada subagente por tarefa. Ele ataca uma causa da lista, o subagente que herda o modelo caro, e nenhuma das outras. Os números dele são a preço de tabela. O efeito sobre as janelas de 5 horas e semanal de uma assinatura não foi medido.

Mesmo o resultado a preço de tabela é pequeno e restrito: cerca de 12% em tarefas mecânicas delegadas, em um teste controlado. Em tarefas naturais complexas, um benchmark aplicou 0 downshifts e outro, 3 de 34. Ainda não há nada atribuível, e não prometo que o limite vai render mais.

Status honesto

Verificado só no Claude Code. Codex e Cursor funcionam, OpenCode está em beta. O número de cerca de 12% é uma estimativa a preço de tabela, de uma execução controlada de um operador em tarefas mecânicas delegadas (checks passaram 12/12 nos dois grupos); em tarefas naturais complexas, ainda não há nada atribuível.

Perguntas frequentes

Por que o limite acaba se eu fiz poucas perguntas?

Cada requisição reenvia o contexto inteiro, e subagentes e cache frio somam mais requisições. O /usage aponta o comportamento que passa de 10% do uso recente.

Trocar para outro modelo devolve o acesso depois do limite semanal?

Não. Segundo a documentação, a janela de sessão e a semanal são compartilhadas entre os modelos. Só uma mensagem de limite específico de um modelo, como o do Opus, deixa continuar em outra família.

O Downshift aumenta o meu limite?

Não há medição disso. O teste controlado mostrou cerca de 12% a preço de tabela, em tarefas mecânicas. O efeito nas janelas da assinatura não foi medido.

Instalar

Rode downshift setup --dry-run antes para ver cada alteração. downshift setup --undo restaura os backups.

curl -fsSL https://raw.githubusercontent.com/tiagovilasboas/downshift/main/install.sh | sh && downshift setup

Plugin do Claude Code

/plugin install downshift --marketplace tiagovilasboas/downshift
