Spawn state: when Downshift works and when it switches

Downshift by Tiago Vilas Boas. Updated 19 October 2026. Source on GitHub

Downshift here is a Go tool for AI coding agents, not the React downshift autocomplete library and unrelated to any car transmission.

Downshift by Tiago Vilas Boas https://github.com/tiagovilasboas/downshift

Every subagent spawn the hook sees gets exactly one state, computed once in internal/telemetry/spawn_state.go from the decision event. Every harness gets it through the shared runner (runHookAdapter); no adapter holds any of it.

State Meaning
switched Downshift changed the spawn's model or effort
held A change was considered; a guardrail (HELD_*), the credit gate or a guessed baseline kept the spawn as it was. Doubt never spends money
observed Downshift looked and had nothing to change
paused downshift session --pause: classified and logged, never changed
control Control group or DOWNSHIFT_NO_ROUTE=1: classified, never changed
blocked A policy-mode harness (KiroCrew) denied the spawn for a respawn

Held wins over switched: a hold means the change was not applied.

Where it shows

Surface What you see Harnesses
stderr, one line per spawn downshift: spawn switched opus → haiku, effort high → low · TRIVIAL, spawn held on opus (would be haiku) [HELD_UNCONFIDENT_DOWNSHIFT], spawn observed, spawn unchanged on opus all (whether the harness UI shows hook stderr is harness-dependent; see the matrix)
downshift watch first line: ● downshift active · last spawn 12s ago: ... or ○ downshift idle · ... (idle after 5 min without a spawn); then the tree all
downshift session / --json header N switched, M held; each row's reason starts switched from <model>; JSON rows carry state, from_model, reason_codes, and the view switched, held all
statusline ◆ downshift · 3 subagents · 2 switched · 1 held · ... harnesses with a statusline bridge
live.json the record below, for a panel all

Idle means no recent spawn. The hook only runs when a subagent is spawned, so it cannot show a heartbeat between spawns.

live.json (for panels and mods)

Written atomically next to the event log (~/.downshift/live.json, or beside DOWNSHIFT_EVENT_LOG) on every spawn. Best effort and fail-open: a write failure never delays or blocks a spawn. No prompt, task text, file path, raw session or agent id is stored; session is the first 8 hex of the hashed id.

{
  "updated": "2026-10-19T12:00:00.123Z",
  "session": "a1b2c3d4",
  "counts": {"switched": 2, "held": 1, "observed": 4},
  "last": {
    "state": "switched",
    "harness": "claude-code",
    "session": "a1b2c3d4",
    "time": "2026-10-19T12:00:00.123Z",
    "from_model": "claude-opus-5-5",
    "to_model": "claude-haiku-4-5",
    "from_effort": "high",
    "to_effort": "low",
    "recommended_model": "",
    "complexity": "TRIVIAL",
    "reason_codes": ["CLASSIFIER_CONFIDENT"]
  }
}

counts reset when the session changes. A reader treats updated older than 5 minutes as idle. For held, to_model is what the child runs on and recommended_model is what Downshift would have chosen.

downshift session --panel (what the agents panel reads)

Prompt-free JSON for the selected session (latest, or --session), built in telemetry.BuildPanel. Ready-made labels, so a panel only draws:

{"session":"a1b2c3d4","switched":2,"held":1,"observed":4,
 "tokens":{"children":4,"saved_children":2,"work_tokens":5200,"work_saved":3200,
           "cache_tokens":180000,"cache_saved":104000},
 "tokens_line":"tokens saved: work 62% · cache 58% (107k of 185k)",
 "by_agent_type":[{"agent_type":"general-purpose","tokens":{...},
                   "line":"general-purpose: work 70% · cache 64% (2 of 3 agents)"}],
 "spawns":[{"tool_use":"<sha256 hex>","state":"switched",
            "from_model":"claude-opus-5-5","to_model":"claude-sonnet-5-5",
            "label":"opus → sonnet (mid)",
            "tokens":{...},"tokens_label":"48k tokens · saved from opus"}]}

Labels: opus → sonnet (mid), held: original model kept, kept, control (unrouted), paused (unrouted), blocked: respawn on another model. tool_use is telemetry.ToolUseKey(tool_use_id): sha256 of harness-downshift-session-v1: + the harness tool call id.

Tokens, never dollars (owner decision 2026-10-19). "Saved" means a child's tokens ran on a cheaper model than the one requested (telemetry.TokenSavings, the same buckets as stats --export tokens_rerouted); work (input+output) and cache (read+write) are counted apart. tokens_line and tokens_label are "" until a child's tokens are known; a reader then draws no figure. A child on a pricier model reads pricier than <model> and adds to work_pricier / cache_pricier, never to the saved share. Control, held, kept and refuted children count in the totals. Harnesses with no proven token source (Cursor, Codex, OpenCode today) have no token figures, never zeros. Dollars: downshift report, priced at report time.

The same figures appear in downshift session (header, a tokens column per row, a by agent type line), the statusline (tokens saved work N% · cache M%), downshift watch, dsmon and the child-end line (48k tokens (work 2.1k, cache 46k) · saved from opus).

mods/savvy-progress

Vendored, so it is patched only through its documented local patch (mods/savvy-progress/downshift-local.patch, README section "Downshift local patch"). The patch runs downshift session --panel and draws the row label (with the agent's tokens_label), the summary line (Downshift tokens saved: …) in the panel and the band, and the by agent type line in the panel header; with no binary or bad output it draws what upstream draws. No routing logic lives in the mod.

What a harness cannot honor

Computing the state is not conditional on the harness. What varies is only display: the child-end line and statusline need CanShowChildLine / a statusline bridge (see harness-matrix.md), and a harness may not show hook stderr in its UI. live.json, downshift watch and downshift session work for every harness that logs spawns.
