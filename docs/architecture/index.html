What Downshift is

A single Go binary (downshift) that runs as a harness hook (JSON on stdin, JSON on stdout) and as an offline CLI over its own event log. On the hook path it classifies the task a main agent delegates, applies policy, catalog and session rules, and returns an updated tool input with model (and, where the harness takes it, reasoning_effort) rewritten. Around that one decision it keeps the evidence needed to say whether the rewrite was honored, what the child used, and whether routing beat a measured baseline.

Read it as an optimization layer for agent execution, not only a router: one deterministic decision per delegation, guardrails that hold under doubt, observation of what the harness then did, and offline evaluation that feeds the next policy change. The hook itself stays small: no network, no LLM, no prompt storage on the hot path, and every failure fails open.

Read the decision, then the execution

BDI is a conceptual lens: task and session facts are beliefs, fixed safety and capability goals are desires, and a checked routing plan is an intention. Downshift implements deterministic routing, not a BDI framework or an LLM planner. Available observations support offline review rather than automatic policy updates.

Step by step, with what the code does

  1. Task, planning, delegation [H]. The main agent decides on its own when to delegate. Downshift sees nothing until the harness fires the hook on the spawn tool (Agent|Task, spawn_agent, invoke_subagent, spawn_run; cmd/downshift/setup_targets.go).
  2. Hook runner and adapter [D]. runHookAdapter (cmd/downshift/main.go) is shared by every harness through harnessRegistry (harnesses.go). It bounds stdin (1 MiB, 2 s read timeout), parses the payload, sets the 1.5 s hook deadline and ProjectDir, recovers a panic into an allow, and only then calls the adapter's Handle. The catalog loads through loadCatalogFailOpen (catalogload.go): a panic in the embedded data or a hostile user override leaves the spawn unchanged instead of exiting 2, which a harness reads as a deny. Adapters (internal/adapters/<harness>) parse fields, declare HarnessCapabilities, call core and encode the wire response. No policy.
  3. Reference model and session [D]. The Claude Code adapter resolves the model the child would have run on: the call's model, the payload model, CLAUDE_CODE_SUBAGENT_MODEL for inheriting agent types, the last assistant message in the parent transcript tail (bounded 400 ms wait), and finally the configured model (ANTHROPIC_MODEL, settings*.json), which is marked as a guess and may only downshift to the small tier. The session list comes from hook lists, session-models.json, discovery, or (Claude Code only) inference from the current model, never above it. Quota marks come from the hook payload, the quota.json cache or an opt-in native export file; a hook never calls a provider. Every adapter calls ResolveSessionModels before classification: exact session metadata takes precedence, and the catalog supplies optional fallback metadata. The session is the complete candidate set. Declared capability order can rank new IDs; an unordered native inventory cannot. Malformed metadata rejects its ID instead of reopening catalog or positional fallback. Missing prices remain unknown, including family matches to a different generation. See session models.
  4. Classification and risk [D]. classifyTask (internal/core/policy.go) runs the signal scorer, the monotonic hash semantic boost, the risk floor and risk abstention (internal/classify/risk.go; from 64 KiB the candidate risk categories are scanned concurrently, same results and order), and the naive-Bayes second opinion.
  5. Route, guardrails, floor [D]. Route resolves tier, effort and the session-resolved model, compares with the current model, then Check (selfcheck.go) applies R1, R2, R4, R5, R6, R7, R8, R9 (R3 retired): any violation turns the safe verdict into OK, which keeps the current model. Only a deterministic lift (risk, opted-in NB upshift, operator floor) may move up. The project floor (internal/policyfile, TierFloorHook) runs after Check and re-checks. Adapt memory records a would-be tier and does not change it; the capability score path runs only with DOWNSHIFT_SCORE_ROUTING=1 and behind the same safe-verdict gate.
  6. Session plan and fate [D]. PlanSession holds foreign ids, preserves explicit_only models, keeps the model when the session is unknown, and selects the session model at the needed tier, skipping exhausted quota. The runner then applies the control group (DOWNSHIFT_CONTROL_SHARE, default 0.10), the per-session pause and DOWNSHIFT_NO_ROUTE: those spawns pass unchanged and are logged as baseline. Otherwise the wire emits updatedInput with only model and reasoning_effort changed; kirocrew has no rewrite channel and gets a block-with-reason instead.
  7. Subagent execution [H]. The harness decides whether the rewrite takes effect. Observed on Claude Code; inferred on Codex; unconfirmed on Cursor (dropped on Free and legacy Pro). Antigravity has limited experimental proof on one build; KiroCrew uses policy and retry. Grok is config-only. Downshift does not run the child, cannot see its context, and never edits what it returns.
  8. Child end and usage [D] from [H] payloads. PostToolUse on Claude Code is the launch of an async child: it carries resolvedModel (honored or refuted) and no tokens. SubagentStop supplies the child transcript, from which the shared recorder (internal/childend) records token counts and model. Current usage records contain no dollar amount. A nil port stays unobserved; absence is never inferred. Per-step routing latency is not a supported telemetry measurement. Claude Code also records the last recognized check command's result as verification: passed|failed|none; this is a transcript sensor, not proof that the implementation is correct. Verification guide.
  9. Telemetry and read-outs [D]. events.jsonl holds routing metadata only (no prompts, tasks or paths). Appends do not fsync (a power loss can drop the last events; a process crash cannot). telemetry.TokenSavings is the single tokens-saved definition (work and cache apart, per agent type) shared by stats, the session views and dsmon; none of them shows a dollar, and neither does report. report compares routed spawns with the control group, counting "completed" only for harnesses that declare an end event and have end records; verification-report groups observed usage-event counts, verification coverage/status and token-call counts by tier; it reports no price or cost; session and watch read the same log.
  10. Benchmarks and tuning [D], offline. benchmark scores the classifier on labelled fixtures (tier accuracy, unsafe downgrade, over-routing); eval-outcome runs the outcome suite (minimal fixtures in OSS, full suite in downshift-labs; it compiles and runs task and model-written Go code and runs the --solver string through sh -c, with no sandbox, so it is for maintainers on task sets they trust); feedback attaches success/retry/failed to a routing id, and only reviewed required_tier labels enter train; shadow-report compares candidate classifiers that never touched a route.

Data flows

Spawn routing (hook path). harness PreToolUse → runHookAdapter (1 MiB, 2 s read, 1.5 s deadline, panic → allow) → adapter parses → ResolveSessionModels → core.Route (classify, fuse, risk, Check, tier floor) → PlanSession → control group, pause and DOWNSHIFT_NO_ROUTE → wire updatedInput (or block-with-reason for kirocrew) → two prompt-free appends (events.jsonl, loop-events.jsonl).

Prompt and DCI (opt-in). UserPromptSubmit → dci_hook.go (1 MiB cap) → codeintel (cache, BM25, abstain, pack within the byte budget) → stdout adds a <downshift-code-context> block, or nothing. Imports no routing package. Measured only for latency and bytes (dci-events.jsonl); no benefit to answer quality or cost is claimed.

Output compaction (observe only). PostToolUse → sensor records tool output bytes and the reduction safe mode would reach → {} (plus an optional status line). The model never sees a shorter result. Compaction only happens when the user pipes output through downshift context compress. Claude Code hooks cannot rewrite tool output, so measure-only is a platform limit, not a choice.

Telemetry and stats. appenders (telemetry, childend, hookport) write JSONL; stats, report, session, watch and dsmon read it. telemetry.Summarize reports gross, pricier-tier and net token counts from observed usage; no prices enter this summary. stats also shows dimensionless normalised units. prices_as_of dates the catalog snapshot used for routing and price analysis, not a dollar figure in current reports.

Trust boundaries

Boundary Control
Harness → hook stdin Untrusted JSON. 1 MiB cap (+1 byte detects overflow), 2 s read timeout (hookReadTimeout), strict parse; any failure is a logged fail-open allow
Hook runtime 1.5 s HookBudget for helper commands, panic recovery, catalog loaded under recover; a failure never exits 2 (deny) and an unchanged Claude Code or Codex spawn answers {}, not an explicit allow, so the user's ask rules still apply (Cursor's wire requires {"permission":"allow"})
Hook → network None. No provider call, no LLM, no price fetch. Quota and prices come from files
State directory Single-user local files; 0700 dirs, 0600 logs; the DCI telemetry log refuses symlinks and non-regular files
Vendored mods Third-party code pinned in NOTICE, read-only, no routing logic; setup installs them through claude plugin install
Release goreleaser pinned to an exact version; build provenance attested for every archive (gh attestation verify)

CI and release guards

  • scripts/ci-classify-changes.sh decides whether Go tests run. It is an allowlist: only existing images under docs/ are provably inert, so every other path, including Markdown (read by internal/docscheck), embedded JSON and .goreleaser.yml, runs Go. An empty diff, or a tag, also runs Go. The classifier has its own test (scripts/test-ci-classify-changes.sh).
  • Pushes to main are never cancelled by a newer run; only superseded pull request runs are. A cancelled code run followed by a skipped docs run once left main unverified.
  • ci-full (weekdays) runs go test -race -cover ./... and govulncheck; the per-PR job does not run the race detector.
  • sync-prices (Mondays, workflow_dispatch) refreshes the embedded list prices and prices_as_of, runs the catalog tests and opens a PR; a person merges it. It dispatches ci on its branch because a PR opened with GITHUB_TOKEN cannot trigger pull_request runs.
  • Release: goreleaser at an exact version, then attest-build-provenance.

Guide and sensor map

This is the outer harness around a coding agent (model + vendor harness + user harness). Each concern has a guide before execution and a sensor after it; sensor coverage depends on the harness, not just on emitted JSON.

Concern / axis Guia (feedforward) Sensor (feedback) Coverage
Routing safety / behaviour Session metadata and project policy contract (inferencial); shared guards and tier floors (computacional) Resolver, guardrail and all-adapter conformance tests (computacional) Shared core; a passing test does not prove native rewrite honor
Cross-harness architecture / architecture fitness Adapters parse/emit; policy stays in shared code (inferencial, AGENTS.md) Conformance tests and code review against that boundary (computacional + inferencial) Repository / PR / CI
Cost and outcome / behaviour Control-group and evidence protocol (inferencial) Honor, child-end and usage records; report and verification-report (computacional) Claude Code has the most complete records; absent evidence stays unknown
Privacy and upkeep / maintainability Prompt-free telemetry and bounded hook I/O contracts (inferencial) Existing privacy, payload and documentation checks (computacional) Repository checks; metadata rather than raw task text is persisted

Human review decides whether offline findings justify a policy change. The verification sensor observes a check result; it does not replace acceptance tests, a security review or a production signal.

What Downshift is not

  • Not an HTTP proxy. Nothing sits between the harness and the model API.
  • Not an LLM-in-the-loop router. Classification is a scored signal table, a hash embedder and a naive-Bayes opinion, all local and deterministic.
  • Does not edit tool results in flight. The PostToolUse hook returns {} (plus an optional status line); context compression is observe-only unless the user pipes output through downshift context compress themselves.
  • Does not store prompts. Task text stays in memory for feature extraction; the event log, feedback store, probe and telemetry carry metadata only.
  • Does not run the subagent or guarantee the rewrite. The harness executes and may ignore updatedInput; the matrix records what each one honors.

Domain Architecture Layers (Clean Architecture / SRP)

Downshift's codebase and documentation are structured strictly according to Clean Architecture, Single Responsibility (SRP), and the Dependency Inversion Principle. Dependencies point inward toward core domain policies; autonomous subsystems like Code Intelligence maintain absolute decoupling from routing logic; and interface adapters contain zero business policy.

internal/quotamodel Pure quota evidence types: Status, Window, Snapshot, Validate, Evaluate, Abandoned, SourceName. No file I/O. Landed: core imports this package; file reads and native parsing enter through LoadQuotaHook, LoadNativeQuotaHook, ParseNativeQuotaHook and RegisterNativeQuotaHook, registered by quota, the same pattern as MemoryAdjustHook
internal/session SessionList and the loaders that do not need Decision or Resolver: file, hook marks, discovered file, quota snapshot attachment. Landed (5f94e07): core imports this package; this package must not import core. PlanForSession, RouteForSession, InferSessionFromCurrent and CanWriteSessionID stay in core
internal/fuse Landed (110ef31). Semantic boost policy: raise-only, no-signal skip. Imports classify and semantic. Does not import core. core keeps ClassifyWithSemantic as a wrapper. Stays in-process and does not exec
internal/nbopinion Landed (4d3e857, PR 156). Hook funcs that call nbtier.Suggest and nbtier.Trivial, registered in init. May import core and nbtier. Core production sources do not import this package or nbtier. NBUpshift and NBDownshift stay on Decision in core. cmd blank-imports this package so init runs. Stays in-process and does not exec. Env stays a typed snapshot set at the edge (SetConfig)
internal/classify Regex classifier, signals.go, language guard, risk floor (concurrent category scan from 64 KiB). No tier, no harness, no catalog
internal/catalog Embedded catalog.json (with prices_as_of), user override merge (recovers into the embedded data on a panic), Resolver
internal/discovery, internal/models Session model discovery (sources, order, discovered.json cache; run by setup and models discover) and models list/check/pull. Both import catalog and core
internal/adapters/* Harness-specific I/O only. Adapters do not choose the tier; they call core.Route, then apply the plan core returns
internal/policyfile, internal/adapt, internal/routeadapt, internal/scoreindex Project tier floor (TierFloorHook), shadow tier memory (MemoryAdjustHook) and the score cache (ScoreHook), plugged into core at init. cmd blank-imports the first three kinds and imports scoreindex directly
internal/quota, internal/hookctx, internal/hookutil Offline budget evidence (file I/O); per-hook deadline and project dir; shared field helpers. quota keeps Load, Store, ParseNative and native registration, aliases the quotamodel types so adapters can keep saying quota.Snapshot, and registers LoadQuotaHook and the native quota hooks. Core production sources do not import quota
internal/hookport, internal/childend Honor, usage and child-end contract; one shared recorder for every harness
internal/telemetry Append-only local JSONL (no per-spawn fsync); prompt-free events; Summarize (single savings definition), stats, report, control group, session tree. Imports core (tiers, prices) and codeintel (DCI summary type in the export)
internal/contextopt, internal/compressor, internal/sensor Context optimization registry, native compressor (observe/safe), tool-output sensor
internal/codeintel Downshift Code Intelligence (DCI): pure Go symbol extraction, incremental inverted index, BM25 ranking, abstention, and structural context packager. Isolated from routing: imports only paths; core and classify do not import it (telemetry imports it for the stats export type).
internal/semantic, internal/nbtier In-process hash embedder (semantic) and naive-Bayes opinion (nbtier). The raise-only boost policy lives in internal/fuse. nbopinion calls nbtier.Suggest and nbtier.Trivial. Core production sources do not import nbtier. The semantic boost and the naive-Bayes opinion stay in-process and do not exec
internal/routingv2/*, internal/decisionintelligence, internal/outcome, internal/benchmark Shadow classifiers and training, advisory recommendation, outcome evals, classifier KPIs. the routingv2/router and matcher packages and internal/routecache were removed on 2026-10-19 (no production importer)
cmd/downshift CLI, harnessRegistry, runHookAdapter, runEnd, setup, doctor. Blank-imports nbopinion, policyfile, quota, routeadapt

Invariants: adapters embed no routing rules; adding a harness is one harnessRegistry entry plus its adapter package, with a port entry only when that harness's own hook sends honor or usage fields; a nil port is unobserved, never inferred. Dependency check: internal/archtest (TestImportGraph, run by go test ./... in the test job) fails when the production closure of core reaches quota, nbtier, nbopinion, catalog, telemetry, adapt, policyfile, scoreindex or an adapter, when session or fuse reach core, or when codeintel reaches core or classify; a negative test proves the matcher detects a violation. Rules not listed there (for example adapters importing policy) are still manual: go list -deps ./internal/<pkg>.

Configuration on disk

State directory ~/.downshift/ (legacy ~/.harness-downshift/, see rename.md; override with DOWNSHIFT_STATE_DIR). See "Where state lives" below for what each file is and its permissions. Per project: .downshift/policy.json (tier floor). Overrides: DOWNSHIFT_EVENT_LOG, DOWNSHIFT_SESSION_MODELS, DOWNSHIFT_QUIET, flags in README and minilm-semantic.md.

Packaging layers (what an agent harness loads)

Besides the Go layers above, the repository is laid out as the five things a coding harness can load. Each is a thin surface over the same binary; none holds policy. The plugin is Claude Code only; every other harness reaches the same layers through downshift setup and the docs.

Layer Path Holds Harness-neutral?
1 Memory AGENTS.md (CLAUDE.md points to it) always-loaded rules, at most 200 lines yes
2 Skills skills/downshift-setup, skills/downshift-audit, skills/cost-reducer procedures with judgment; detail in references/ on demand yes (SKILL.md format)
3 Hooks the downshift <harness> subcommands; hooks/hooks.json is the plugin form routing, telemetry, guardrails (shared Go) yes; hooks.json is Claude Code packaging
4 Agents agents/mechanical-worker.md one example with no pinned model (subagents.md) Claude Code format; the rule applies everywhere
5 Plugin and mods .claude-plugin/plugin.json, marketplace.json, mods/ one install: hooks, command, skills, agent; sibling mods (savvy-progress, filetree, downshift-dock) that setup installs Claude Code only

Contributor-only skills (.claude/skills/downshift-layering) stay out of the plugin. Companions (Headroom) are detected and documented, never bundled: companions.md.

Known gaps and limits

These are real and open on 2026-10-19. Nothing here is hidden elsewhere.

  1. telemetry is large. 31 non-test files (events, cost, stats, report, control group, rotation, pause, session tree, completion) behind one package, imported by adapters, childend, hookport and server. A split (event log and appenders vs read-outs) is proposed, not done.
  2. init-registered hooks in core (Fullstack P1-1). The result of core.Route depends on which packages were blank-imported: the tier floor (policyfile), shadow memory (routeadapt), naive-Bayes (nbopinion) and the quota loaders (quota) exist only if cmd/downshift imported them. Adapter tests link quota (adapters import it) but not policyfile, nbopinion or routeadapt, so they run without the tier floor and the opinion. Behaviour is covered at runHookAdapter and core.Route tests, but an adapter test alone does not prove production routing.
  3. No import-graph sensor. The invariants above are checked by hand with go list. There is no test or CI step that fails when core gains a forbidden import.
  4. Rotated log backups are not read. stats prints a note and counts only the live events.jsonl; totals drop after a rotation (100 MB by default).
  5. DCI is opt-in and measured only for latency and injected bytes. No evidence yet that it improves answers or lowers cost.
  6. Savings are token shares, not invoices. stats and report print no dollar. Tokens are observed only where the harness reports them (Claude Code most completely). The earlier trial (2026-10-15) is -12% at list price on mechanical pieces; the four-arm run of 2026-10-21 measured about 24% fewer tokens per accepted run with routing (95% interval +2.1% to +46.7%, one operator, 46 runs). Neither is a general rate.
  7. Compaction is measure-only on Claude Code. Hooks cannot rewrite tool output, so the sensor reports a hypothetical reduction.
  8. Hook latency after removing the per-spawn fsync: p50 8.5 ms, p95 9.7 ms for a Claude Code Task payload (n = 200, Apple M3 Pro, macOS 26.6, Go 1.27.1; downshift version p50 7.7 ms; process floor 2.2 ms). Not measured on Linux or Windows, on a populated state directory, or under parallel spawning. Trade-off: a power loss can drop the last events. Evidence.
  9. OpenCode packaging is unverified. The adapter and conformance tests exist; the forwarding plugin (mods/downshift-opencode) has no live spawn observed. Cursor, Codex and Antigravity rewrite honor is also bounded as in the harness matrix.
  10. Stale diagram source. docs/img/architecture.svg (and -dark) is hand-drawn, not generated, and predates classify, fuse, session, opencode and the hook ports; it still names e5 and graphify helpers. Nothing links to it. The ASCII diagram above is the maintained one. downshift-bdi and downshift-execution are current.
  11. Dead-end packages. Removed on 2026-10-19: internal/routecache, internal/orchestration, internal/routingv2/router and matcher.
