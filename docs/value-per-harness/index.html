Checked against the repository on 2026-10-19: internal/core/capabilities.go (HarnessCapabilities, UsageSource), internal/catalog/catalog.json (updated and prices_as_of 2026-10-19), harness-matrix.md and evidence.md. This page answers one question per harness: how much of "what did routing do for me here" is observed, and how much is arithmetic on list prices. It changes no code and no catalog value.

What a routed spawn changes, and what it does not

Routing does not claim to reduce token counts. The child runs on a different model; the observed token count shows what that child used. Current stats, report and schema 3 export show token counts and coverage, not dollar amounts. Normalized units in stats are dimensionless. Catalog list prices remain metadata for routing policy, not reported savings. A baseline for a model that did not run is a counterfactual (evidence.md).

Two consequences:

  • Where a plan has no per-token bill (Claude Code Pro, Max and Team; Cursor plans; a Codex or Antigravity plan quota), the invoice does not move with the model in the way list prices suggest. Tokens by tier (how many observed tokens ran on the small, mid and frontier model) is the more faithful figure there, because it is what was observed. A dollar reading stays a list-price estimate in every case, and Downshift prints none.
  • A catalog price is not an invoice (evidence.md).

Catalog audit: accounting anomalies for "value per API"

Method: read every priced entry of internal/catalog/catalog.json, order the tiers per harness, and check whether a Downshift verdict can move to a pricier model. Whether it can does not depend on a guardrail: compareToCurrentModel (internal/core/policy.go:310-328) decides a downshift from tier rank alone, and Savings (policy.go:39) is informational (SavingsRatio returns 0 when the target is not cheaper, internal/catalog/catalog.go:487-494). No path in internal/core gates a cross-tier downshift on price before an adapter writes the rewrite (price comparisons exist only to order equal-tier native candidates, internal/core/session_native.go:122-131), so a tier inversion in the data is an inversion in the money. RealSavingsUSD clamps each event at zero (internal/telemetry/cost.go:58-70), so this catalog price inversion is a policy/data issue, not a current USD savings output.

# Anomaly Where Can a routed downshift overspend?
1 Codex frontier is priced below mid. gpt-6-sol (frontier, the automatic frontier target) is 2/10 with cache read 0.20; gpt-5.6-terra (mid, the only mid entry) is 2/12 with cache read 0.20. Same input, cache and write prices, output 20% higher on the "cheaper" tier. gpt-6.1-sol (frontier) is 2/10 with cache read 0.10, so terra costs more on cache reads too internal/catalog/catalog.json:405-418 (gpt-6-sol), :419-432 (gpt-6.1-sol), :447-460 (gpt-5.6-terra) Yes. A session on gpt-6-sol or gpt-6.1-sol routed to mid (gpt-5.6-terra) is a Downshift verdict that costs about 20% more on output and, from gpt-6.1-sol, 2x on cached reads. gpt-5.6-sol (4/20) to terra (2/12) does save. Also the reverse: a mid-to-frontier upshift from terra to gpt-6-sol is cheaper. Verified 2026-10-19 against https://developers.openai.com/api/docs/pricing: OpenAI lists exactly these prices, so the inversion is the vendor's list price, not a data error. Fixing it is a tier or routing decision, not a price edit
2 Cursor frontier below mid. grok-4.7-xhigh (frontier) is 2/6; the automatic mid claude-4.5-sonnet-thinking is 3/15. 5 OpenCode entries carry no prices at all. 7 Haiku 5.5 stored at its low-volume price. claude-haiku-5-5 is 0.1/0.5 up to 100k prompt tokens and 0.5/2.5 above; the catalog stores the first. Not anomalies, checked: KiroCrew is monotonic across all three pairs (claude-haiku-4-5 1/5, claude-sonnet-5-5 2/10, claude-opus-5-5 4/20), and so is the Claude Code Anthropic ladder and the Cursor automatic ladder (1/5, 3/15, 5/25). The inversions above appear only through non-default session models (1 to 3) or equal prices (4).

Proposals, not applied

  1. A price guard on the shared downshift path, not a catalog edit. One check in core (for example in Check, internal/core/selfcheck.go) holding a downshift whose target costs at least as much as the current model when both are priced (from.InputM + from.OutputM <= to.InputM + to.OutputM), with a reason code. That serves every harness by the layering rule and removes the overspend for anomalies 1 to 3 whatever the data later contains. It needs a regression test on the codex pair. This is a Go change owned by the fullstack front, so it is only proposed here.
  2. A catalog coherence test per harness: for each harness, automatic small, mid and frontier targets must be non-decreasing in input plus output price, and a documented exception list for the rest. go test ./internal/catalog already checks cache multipliers and missing prices (docs/reference/prices.md); tier order is not checked.
  3. Re-verify the codex row: done 2026-10-19. The OpenAI page lists gpt-6-sol at 2/10 and gpt-5.6-terra at 2/12, so the data is right: the codex mid tier is not a cost tier, and gpt-6-luna is the only real downshift target on that harness until the tiers change.
  4. OpenCode: child usage tokens remain unobserved; current reports show token counts where the harness provides them and no dollar amounts.
  5. Cursor: add cache prices from the vendor: done 2026-10-19 (anomaly 6).
  6. Antigravity: verify flash_lite against flash; if equal, say a mid-to-small move there saves $0.

What to read on each harness

If you run Trust Do not read as
Claude Code on an API key Observed child tokens, refuted rewrites excluded (no dollar printed) An invoice: parent session tokens are not in it
Claude Code on Pro, Max or Team Observed child tokens by model and tier; the number of spawns moved to a cheaper or pricier model Dollars saved: there is no per-token bill to save against
Cursor Decisions and rewrites emitted; model changes are unconfirmed on usage-based plans and discarded on Free and legacy Pro Any token or dollar figure: none is recorded
Codex Decisions, effort and model emitted; honored inferred Any token or dollar figure: none is recorded; the catalog's frontier-below-mid order (anomaly 1) is unresolved
OpenCode Decisions only, beta Any figure; no price, no tokens, no live spawn
Antigravity, KiroCrew Decisions, one observed child on Antigravity, one block and retry on KiroCrew Any token or dollar figure

Tokens rerouted, the metric that counts the tokens of usage records linked to applied, non-refuted rewrites by harness and requested-to-ran model pair, is defined in evidence.md as rung B evidence. Its fields and command output are documented in stats-export.md.
