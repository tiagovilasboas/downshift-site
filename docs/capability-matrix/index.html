This reference is split in two pages to keep each one light. Part 2 continues with the later sections: Downshift capability matrix, part 2: context and packaging.

Downshift by Tiago Vilas Boas · https://github.com/tiagovilasboas/downshift

Audit date: 2026-10-17. Source of truth for writers: every row below was read from code, tests or a dated evidence file in this repository, not from existing marketing text. When a public doc says more than a row supports, the doc is listed in Contradictions and overclaims found.

Status vocabulary (one of five): Implemented means code, tests and at least one dated observation on a real harness. Implemented, not validated everywhere means the code is shared but the effect was observed on some harnesses or plans only. Experimental means shipped behind a flag or a maintainer command, with no production claim. Planned means documented intent with no code path. Not supported means the harness or design cannot do it.

Harness status words (Completed, Functional, Beta, Experimental) are a different scale and are defined in harness-matrix.md; they appear only in section 4.

Shorthand: core is internal/core, cmd is cmd/downshift, "matrix" is docs/reference/harness-matrix.md, "A/B" is docs/evidence/subagent-routing-ab-2026-10-15.md, "audit" is docs/evidence/hardening-audit-2026-10-15.md.
