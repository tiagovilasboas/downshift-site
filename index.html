Your best model shouldn't do every job.

Downshift is a free tool for coding agents such as Claude Code. When the agent hands a simple task to a helper, a subagent, Downshift runs it on a smaller, cheaper model. Hard, risky or unclear tasks stay on the model you chose. It runs on your machine, with no other AI call to decide.

Who it is for

Downshift acts when your coding agent delegates a task. What you gain depends on how you pay for the model.

  • Your agent delegates work

    If your agent creates subagents (Claude Code, Codex, Cursor, OpenCode), Downshift picks the model for each one. With no subagents, there is nothing to switch.

  • You pay per token (API)

    Mechanical work on a smaller model costs less per token. downshift report shows dollars per completed task, against a control group.

  • You are on a plan (Pro, Max, Team)

    There is no per-token bill. Downshift shows how many tokens ran on a smaller model. How much that stretches your plan's limit is not measured yet.

Not for: choosing the model of your main conversation, or deciding whether to delegate.

Why Claude Code subagents overspend, and why few people measure it.

Three behaviors of today's coding agents. Downshift, a single Go binary with no daemon that hooks into your agent, acts on each one.

  1. Subagents inherit your most expensive model

    What happens
    A subagent with no pinned model runs on the session model. Renaming a variable, listing files and fixing a typo get the same model as an architecture review.
    What it costs
    Mechanical work is billed at the frontier list price: $4 and $20 per million input and output tokens on Opus, against $1 and $5 on Haiku.

    What Downshift does

    A local hook scores the task and rewrites the model to a right-sized one, only when it is confident.

  2. After a break, the next message pays for the whole conversation again

    What happens
    Claude keeps the recent conversation in a cache, which makes the next message cheaper. After an hour without requests the cache expires, and the next message re-sends the whole conversation into it.
    What it costs
    In the cache-tax mod's own example, one such send re-writes 200,502 tokens, priced at $4.01.

    What Downshift does

    In a conversation of 50k tokens or more, cache-tax stops that message once, shows its estimated price and lets you decide. /keepwarm keeps the cache alive through a break, if you turn it on.

  3. Savings are claimed more often than they are measured

    What happens
    A list-price estimate is not an invoice, and two runs of the same agent can differ a lot on their own. In the controlled trial, the routed runs of one batch took about half the turns of the control (13.9 against 30.6) with no downshift applied.
    What it costs
    A cost gap between two runs can be the agent's own variation, not routing.

    What Downshift does

    Downshift leaves about 1 in 10 spawns unrouted as a control group, keeps telemetry without prompts, and treats every figure as an estimate until downshift report or your invoice confirms it.

Out of scope: deciding whether to delegate at all. Downshift does not decide that.

Send the code a change touches, not the whole repo.

Code intelligence is opt-in (downshift dci enable). For a symbol, it finds the impact radius: the callers a change can reach. It then packs only the affected symbols under a byte cap, so the agent starts with the relevant code.

A cold prompt cache makes the next send expensive. The cache-tax mod (Claude Code 2.1.287 or later) prices it first. A cold send on a context of 50k or more is held once, with its estimated rewrite price, so you decide.

The honest limit of output compaction

In Claude Code, a hook cannot rewrite tool output in flight. The native provider measures bytes and saves no tokens there. Real in-flight compression needs a proxy such as Headroom. Downshift detects and records it. It never starts it.

Claude Code model routing, step by step.

What happens between the agent spawning a subagent and the subagent running. Every step is code in the repository.

  1. 1

    Harness

    The agent spawns a subagent

    Agent / Task

    The main agent delegates through its spawn tool: Agent or Task, spawn_agent, invoke_subagent. Downshift sees nothing until the harness fires its pre-tool hook.

  2. 2

    Downshift

    The hook starts the shared runner

    runHookAdapter

    runHookAdapter reads the payload from stdin, capped at 1 MiB with a 2 s read timeout, sets a 1.5 s budget, and turns any panic into an unchanged spawn.

  3. 3

    Downshift

    The adapter parses the payload

    internal/adapters

    The harness adapter reads the task text, the model the child would run on and the session. It declares what the harness can do and holds no policy.

  4. 4

    Downshift

    core.Route classifies the task

    internal/classify

    Weighted signals in English and Portuguese give TRIVIAL, SIMPLE, MEDIUM or COMPLEX, which maps to a tier: small, mid or frontier. A prompt with no signal defaults to mid and abstains.

  5. 5

    Downshift

    The semantic boost can only raise

    internal/fuse

    An in-process word-hash step may lift a hesitant class. It never lowers a tier, never boosts a prompt with no signal and never creates COMPLEX on its own.

  6. 6

    Downshift

    Floors and guardrails check the result

    selfcheck.go R1-R9

    The risk floor, guardrails R1 to R9 and the project floor in .downshift/policy.json run next. The session model list and the quota gate decide what can be written. Any hit means: keep the model.

  7. 7

    Downshift

    Decide: rewrite or hold

    updatedInput

    If it is confident and safe, the hook returns updatedInput with only the model changed, plus reasoning_effort where the harness takes it. Otherwise the spawn goes through as asked. About 1 in 10 spawns is left unrouted on purpose, as the control group.

  8. 8

    Harness, then Downshift

    The subagent runs, then telemetry records it

    events.jsonl

    The harness runs the child on the written model, or ignores the rewrite, which Downshift cannot control. Downshift then appends counts, hashes, timings and, on Claude Code, priced tokens to events.jsonl. No prompt text.

What never happens

  • No LLM call to choose a model.
  • No prompt, task text or file path is stored. Telemetry holds counts, hashes and timings.
  • No rewrite when it is unsure. When unsure, nothing changes: no cheaper model and no pricier one.
  • No downshift of a COMPLEX task, or of a task that touches a risk category such as auth, payments or secrets.
  • No explicit_only model is replaced, and no model id from another harness is written.
  • No blocked spawn because of an error. A bad payload, a panic or a timeout leaves the spawn unchanged.

Rules it always follows

  • Local classification. Each task is scored on your machine with signals and a model catalog. No LLM call. Prompts are evaluated in memory and never stored.
  • Fail-open. Any error or missing capability leaves the spawn untouched. Downshift only changes the model and effort fields.
  • Doubt keeps your model. Unsure? The spawn keeps the model it asked for. Doubt never spends money, and a cheaper pick without confidence is held.
  • Risk floors. Payments, auth and secrets are protected. Migrating a payment webhook stayed on opus. Rotating production secrets kept its original model.
Telemetry, control group and reportsRecords what happened and compares routed spawns with an unrouted control.Implemented
  • events.jsonl: counts, hashes, timings
  • downshift stats, session and watch: switched, held or observed per spawn
  • downshift report: cost and tokens per completed task, routed against control
  • 10% control group (DOWNSHIFT_CONTROL_SHARE)

One controlled trial so far. report prints no saving under 20 completed tasks per group, and token usage is recorded on Claude Code only.

Frequently asked questions

Does Downshift call an LLM to pick a model?

No. Routing uses scored signals and a model catalog, locally. No extra tokens and no extra model call in the spawn path.

Do I need another API key?

No. Routing runs locally and makes no LLM call, so it needs no key. The subagent's work still runs through your harness and your plan, as before.

What happens when Downshift is unsure?

The spawn keeps the model it asked for. Doubt never spends money. Downshift is also fail-open: any error or missing capability leaves the spawn untouched.

Which coding agents does it support?

Claude Code is verified. Codex and Cursor are functional. OpenCode is beta. Antigravity and KiroCrew are experimental. The compatibility table on this page separates the hook, the rewrite and the model the subagent actually used.

How much does it save?

In one controlled Claude Code trial, mechanical delegated tasks cost about 12% less at list price, with 12 of 12 validated checks passing. On natural use, no saving is attributable yet. Estimates are not invoices.

How do I reduce Claude Code token usage and costs?

Start with delegated subagent work. Downshift reduces waste in several ways: model routing, context selection and explicit compaction of some outputs (downshift context compress). It routes mechanical subagent tasks to a cheaper tier through a PreToolUse hook and prices a cold prompt cache before you pay for it. It does not promise automatic compression of every token in flight. Estimates are not invoices.

How do I route subagents to cheaper models?

Run the install script, then downshift setup. It adds a hook that scores each subagent spawn and rewrites the model, and the effort where the harness supports it, when it is confident. Risk floors protect auth, payments and secrets. Doubt keeps the original model.

Is Downshift related to the React downshift library?

No. The React downshift library builds accessible autocomplete and dropdown components. This project is an unrelated Go tool that routes AI coding agent subagents to right-sized models.

Is it free?

Yes. Apache-2.0, a single Go binary, no daemon.

Does it change my workflow?

Downshift works inside your agent, as a hook when a subagent starts, and changes only that spawn's model and effort fields. On Claude Code, setup also sets "model": "opusplan" and plan mode as the default, only for keys you have not set. It shows the changes first and keeps your explicit settings. Skip that session policy with --no-session-policy, preview with --dry-run, revert with --undo. Code intelligence is opt-in.

What changes on my machine?

Setup merges hooks into your harness config files, such as Claude Code's settings.json, and saves a timestamped backup first. A project can add an optional .downshift/policy.json tier floor. Nothing runs as a daemon.

Does it slow down a subagent spawn?

It adds one local process call, with no network and no LLM. In one traced run the binary exited in 30 ms. The hard limits are 2 s to read the payload and 1.5 s of hook budget, and an overrun or error leaves the spawn unchanged. On Claude Code it may also wait up to 400 ms for the parent transcript, to learn the current model. That is one trace, not a benchmark.

What if it picks the wrong model?

It rewrites only when it is confident and no guardrail objects. On blind test sets most misses are abstentions, which keep your model. COMPLEX tasks and tasks that touch auth, payments or secrets never go down. In the controlled trial 12 of 12 checks passed in both arms, though checks verify structure, not the quality of wording or design. Run downshift session --why to see why a spawn went where it did, and report a misroute as an issue with the prompt and the tier you expected.

What is stored?

Local state in ~/.downshift: counts, hashes and timings. No prompts, task text or file contents; they are scored in memory and never stored.

Does it touch the network?

Two touches. A detached refresh of public model scores, started after the hook has answered, downloads public files and sends no prompt (DOWNSHIFT_SCORES=off disables it). If you arm /keepwarm, cache-tax pings your own session to keep its cache warm. Routing itself makes no network call; your harness still sends the subagent's work to your model provider, as before.

How do I turn it off?

Pause one session with downshift session --pause, or /downshift:status --pause in Claude Code; the pause expires after 12 hours. Stop all rewriting with DOWNSHIFT_NO_ROUTE=1: Downshift still classifies and logs, but never rewrites. Remove it with downshift setup --undo, which restores the latest backup of your harness config. Code intelligence stays off until you enable it.

How do I see what it did?

downshift session --tree shows the subagents of a session, and --why explains the latest decision with its reason codes. downshift watch follows decisions live. downshift stats shows the tokens saved, and downshift report prices them and compares routed spawns with the control group. To preview a decision before any spawn, run downshift try with your task. downshift doctor checks hooks and state.

What about Cursor and Codex?

Same router and guardrails, different proof. On Codex the rewrite is inferred, not observed. On Cursor it is emitted but unconfirmed, and discarded on Free and legacy Pro plans. Claude Code is the verified one. The compatibility table on this page has the detail per harness.
