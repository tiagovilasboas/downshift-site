How token optimization works

Four capabilities behind one downshift setup, running as native hooks inside your harness.

Deterministic model routing

When the parent delegates small mechanical pieces such as renames, test runs and listings, they get a cheaper tier. Risk floors protect auth, payments and secrets.

Doubt never spends money

When the classifier is unsure, the spawn keeps the model it asked for. Upshifts need confidence.

Prompt cache hygiene

Prices a cold prompt cache before you pay for it and offers /keepwarm across a break.

Context packing

Opt-in AST and call-graph index that packs only the affected symbols under a byte cap.

Right-sized subagentmodel and effort

Claude Code token optimization is mostly a routing problem. Coding agents hand mechanical work such as renames, test runs and file listings to subagents that often inherit the most expensive model and the highest reasoning effort.

Downshift is harness engineering for that gap. It runs as a native hook, scores each delegated task with local signals, and picks a right-sized model and effort from a catalog. When it is unsure, the spawn keeps the model it asked for.

Not the React library. Downshift here is unrelated to the React downshift autocomplete and dropdown library. It is a Go tool for AI coding agents, not a UI component.

Who it is for

  • Developers using Claude Code, Codex or Cursor who delegate work to subagents and watch the token bill.
  • Teams building a coding-agent harness who want deterministic, auditable model routing.
  • Maintainers who want measured results, with a control group, instead of vendor promises.

One router for every AI coding harness

For harness engineers

Every harness gets the same router. Adapters only parse the payload, declare their capabilities and emit the wire response. Pick a harness to see the hook it uses. Behaviour lives in shared layers; adapters only parse and emit. Status is stated as verified, not hoped.

Measured, not promised

Estimates are not invoices. Downshift leaves about 1 in 10 spawns unrouted as a control group, so downshift report can compare routed against control. Prompts are evaluated in memory and never stored. On natural, complex use, nothing is attributable yet, and the docs say so.

Frequently asked questions

What happens when Downshift is unsure?

The spawn keeps the model it asked for. Doubt never spends money, and Downshift is fail-open.

Which coding agents does it support?

Claude Code is verified; Codex and Cursor are functional; OpenCode is beta; Antigravity and KiroCrew are experimental.

Does Downshift call an LLM to pick a model?

No. Scored signals and a catalog, locally, in milliseconds. No extra tokens in the spawn path.

How much does it save?

About 12% list-price on mechanical delegated work in one controlled Claude Code trial. Treat it as an estimate.

How do I reduce Claude Code token usage?

Delegated subagent work is a common place to overspend. Downshift routes mechanical subagent tasks to a cheaper model tier through a PreToolUse hook, warns before a cold prompt cache is paid for, and can pack relevant code context. In one controlled trial, mechanical delegated tasks saved about 12% in list-price cost. Estimates are not invoices.

How do I route subagents to cheaper models?

Install Downshift with its install script and run downshift setup. It adds a hook that scores each subagent spawn and rewrites the model and reasoning effort when it is confident. Risk floors protect auth, payments and secrets, and doubt keeps the original model.

Is Downshift related to the React downshift library?

No. The React downshift library builds accessible autocomplete and dropdown components. This project is an unrelated Go tool that routes AI coding agent subagents to right-sized models.

Is it free?

Yes. Apache-2.0, single Go binary, no daemon.
