Your best model shouldn't do every job.

Downshift gives your coding agent the right model for each subagent, shorter output from clean commands, and, if you turn it on, only the code a change touches. No extra AI call to decide.

Who it is for

Downshift acts when your agent delegates a task. What you gain depends on how you pay.

  • Your agent delegates

    With Claude Code, Codex, Cursor or OpenCode, each subagent gets a model sized for the job. No subagents, nothing to switch.

  • You pay per token

    Mechanical work on a smaller model costs less per token. downshift report shows tokens per completed task, routed against control.

  • You are on a plan (Pro, Max, Team)

    There is no per-token bill. Downshift shows how many tokens ran on a smaller model. What that does to your plan limit is still being measured.

Not for: picking your main model, or deciding whether to delegate.

Where a coding agent spends more than it needs to.

Three leaks. Downshift is one Go binary, no daemon, and acts on each.

  1. Subagents inherit your most expensive model

    Renaming a variable gets the same model as an architecture review.

    Fix

    A local hook scores the task and rewrites the model only when it is confident. In doubt, your model stays.

    Status

    Verified on Claude Code

  2. Routine output fills the context

    A passing test run or a clean git status drops dozens of repeated lines into the context.

    Fix

    downshift compact shortens the clean run. Errors, stack traces and failing output stay byte for byte.

    Status

    Implemented, on by default

  3. The agent reads more code than the change needs

    To change one symbol it opens whole files and hunts for callers.

    Fix

    DCI packs only the affected symbols, under a byte cap.

    Status

    Opt-in. Measured for latency and bytes.

Clean output, smaller context.

Passing test runs and clean builds reach your agent in a line or two. Errors, stack traces, diffs and any failing exit stay exactly as they were.

Compactor is on by default. It runs routine commands through downshift compact, which keeps the exit code and shortens only output it can tell is clean. It wraps every git subcommand and the listed test and build tools (go, pytest, vitest, jest, tsc, cargo, playwright, cypress, phpunit, gradle, maven, flutter, dart, next build). Of the git commands, only git status shrinks; the rest pass through byte for byte.

Automatic rewrite works on Claude Code. In other harnesses your agent runs downshift compact -- <command> directly. This is not the /compact command: it never summarises your conversation.

On the synthetic test corpus (248 files), the 26 that compact shrink by 82.3% in bytes, the best clean ones by 91 to 97%. Across all 248, including failures built to stay raw, the cut is 23.7%. Bytes, not tokens, and not your command mix. Example: a clean git status went from 150 to 61 bytes (2026-10-20).

Turn it off with "exec": false in the config or DOWNSHIFT_EXEC=0.

How it works

Send the code a change touches, not the whole repo.

Ask for a change and the agent starts with the callers and symbols it can reach, packed under a byte cap, instead of opening whole files.

Opt-in (downshift dci enable). It finds the impact radius of a symbol and packs only the affected code. Go by AST; TypeScript, JavaScript, Python, Rust, PHP, Java and C# by pattern.

Example run: 927 files indexed, 3 selected, 1,869 bytes packed (budget 3,500), 5 ms retrieval after a 402 ms index build.

Measured so far: size and latency. Not measured: whether answers get better. Read it as a way to send less, not proof of better answers.

How a spawn gets its model.

Eight steps, all code in the repository. Your agent spawns a subagent; a local hook scores the task; guardrails check it; the hook rewrites the model or leaves it alone; telemetry records counts and timings.

  1. 1

    Harness

    The agent spawns a subagent

    Agent / Task

    The main agent delegates through its spawn tool: Agent or Task, spawn_agent, invoke_subagent. Downshift sees nothing until the harness fires its pre-tool hook.

  2. 2

    Downshift

    The hook starts

    runHookAdapter

    runHookAdapter reads the payload from stdin, capped at 1 MiB with a 2 s read timeout, sets a 1.5 s budget, and turns any panic into an unchanged spawn.

  3. 3

    Downshift

    The adapter reads the payload

    internal/adapters

    The harness adapter reads the task text, the model the child would run on and the session. It declares what the harness can do and holds no policy.

  4. 4

    Downshift

    The task is classified

    internal/classify

    Weighted signals in English and Portuguese give TRIVIAL, SIMPLE, MEDIUM or COMPLEX, which maps to a tier: small, mid or frontier. A prompt with no signal defaults to mid and abstains.

  5. 5

    Downshift

    The semantic step can only raise

    internal/fuse

    An in-process word-hash step may lift a hesitant class. It never lowers a tier, never boosts a prompt with no signal and never creates COMPLEX on its own.

  6. 6

    Downshift

    Floors and guardrails check

    selfcheck.go R1-R9

    The risk floor, guardrails R1 to R9 and the project floor in .downshift/policy.json run next. The session model list and the quota gate decide what can be written. Any hit means: keep the model.

  7. 7

    Downshift

    Rewrite or hold

    updatedInput

    If it is confident and safe, the hook returns updatedInput with only the model changed, plus reasoning_effort where the harness takes it. Otherwise the spawn goes through as asked. About 1 in 10 spawns is left unrouted on purpose, as the control group.

  8. 8

    Harness, then Downshift

    The subagent runs and is recorded

    events.jsonl

    The harness runs the child on the written model, or ignores the rewrite, which Downshift cannot control. Downshift then appends counts, hashes, timings and, on Claude Code, priced tokens to events.jsonl. No prompt text.

What never happens

  • No AI call to pick a model.
  • No prompt, task text or file path stored.
  • No rewrite when unsure.
  • No downshift of complex tasks or of auth, payments or secrets.
  • No blocked spawn because of an error: a bad payload, panic or timeout leaves the spawn unchanged.
  • About 1 in 10 spawns is left unrouted on purpose, as the control group.

Stay in control

GuardrailsHolds any change the evidence does not support and keeps the model you asked for.Implemented
  • R1 to R9 (R3 retired) in selfcheck.go
  • risk floors: secret, authz, crypto, payment, vuln, pii, destructive, concurrency, prompt injection
  • project tier floor in .downshift/policy.json, which only raises
  • quota and credit gate

The quota gate is implemented but not validated on every harness.

Rules it always follows

  • Local classification. Each task is scored on your machine with signals and a model catalog. No LLM call. Prompts are evaluated in memory and never stored.
  • Fail-open. Any error or missing capability leaves the spawn untouched. Downshift only changes the model and effort fields.
  • Doubt keeps your model. Unsure? The spawn keeps the model it asked for. Doubt never spends money, and a cheaper pick without confidence is held.
  • Risk floors. Payments, auth and secrets are protected. Migrating a payment webhook stayed on opus. Rotating production secrets kept its original model.
Telemetry, control group and reportsRecords what happened and compares routed spawns with an unrouted control.Implemented
  • events.jsonl: counts, hashes, timings
  • downshift stats, session and watch: switched, held or observed per spawn
  • downshift report: tokens per completed task, routed against control
  • 10% control group (DOWNSHIFT_CONTROL_SHARE)

One controlled trial so far. report needs 20 completed tasks per group and compares tokens per completed task; child token usage is currently recorded on Claude Code only. stats and report print no dollar amounts.

Install, preview, then write.

Setup shows the diff for every harness it finds before it writes anything, saves a timestamped backup, and --undo restores it.

  1. curl -fsSL https://raw.githubusercontent.com/tiagovilasboas/downshift/main/install.sh | sh

    Download the binary for your platform.

  2. downshift setup --dry-run

    Print the diff. Writes nothing.

  3. downshift setup --yes

    Write the hooks, with a backup. (Run downshift setup to be asked first.)

  4. downshift doctor

    Check the binary, the hooks, state and scores.

  5. downshift try "rename the userId variable"

    See the tier it would pick, and why.

  6. downshift setup --undo

    Restore the latest backup.

Binaries for macOS and Linux (amd64, arm64) and Windows (amd64). On Claude Code, setup also sets the default model to opusplan and plan mode, only for keys you have not set; skip it with --no-session-policy.

Frequently asked questions

Is Compactor the same as /compact?

No. /compact summarises your conversation. Compactor shortens the clean output of commands such as go test and git status, keeps the exit code, and leaves errors and failures exactly as they were.

Does it save my plan limit?

We do not know yet. Downshift shows how many tokens ran on a smaller model; the effect on a plan limit is still being measured.

What is sent anywhere?

Downshift stores no prompts or task text, only counts, hashes and timings, locally. Routing makes no network call. Your harness still sends the subagent's work to your model provider, as before. A detached refresh of public model scores sends no prompt and can be turned off with DOWNSHIFT_SCORES=off.

Will it route to the wrong model?

It rewrites only when it is confident and no guardrail objects; in doubt your model stays, and complex tasks or tasks touching auth, payments or secrets never go down. Run downshift session --why to see any decision, and report a misroute as an issue.

How do I undo it?

downshift setup --undo restores the latest backup of your harness config. Pause one session with downshift session --pause, or stop all rewriting with DOWNSHIFT_NO_ROUTE=1.

Which coding agents does it support?

Claude Code is completed. Codex and Cursor are functional, OpenCode is beta, Antigravity and KiroCrew are experimental. The table above shows what was observed for each.

Is DCI safe to turn on?

It is opt-in and off until you enable it. We measured its size and speed, not whether answers improve, so try it on a branch and compare.

Where is the dashboard?

The web dashboard was removed on 2026-10-20. Use downshift report, downshift stats and downshift session, which show tokens and coverage in the terminal.

Does it call an AI to pick a model? Do I need another key?

No to both. Routing is local, from scored signals and a model catalog, with no extra model call and no key.

How much does it save?

In one controlled Claude Code trial, mechanical delegated tasks cost about 12% less at list price, with 12 of 12 checks passing; checks verify structure, not quality. In everyday use, no saving is attributable yet. Estimates are not invoices.

Is Downshift related to the React downshift library?

No. The React downshift library builds accessible autocomplete and dropdown components. This project is an unrelated Go tool that routes AI coding agent subagents to right-sized models.

Is it free?

Yes. Apache-2.0, a single Go binary, no daemon.

What changes on my machine?

Setup merges hooks into your harness config files, such as Claude Code's settings.json, and saves a timestamped backup first. A project can add an optional .downshift/policy.json tier floor. Nothing runs as a daemon.

Does it slow down a subagent spawn?

It adds one local process call, with no network and no LLM. In one traced run the binary exited in 30 ms. The hard limits are 2 s to read the payload and 1.5 s of hook budget, and an overrun or error leaves the spawn unchanged. On Claude Code it may also wait up to 400 ms for the parent transcript, to learn the current model. That is one trace, not a benchmark.
