Claude Code subagent model: which one does a subagent run on?

Downshift by Tiago Vilas Boas. Updated 19 October 2026

Downshift here is a Go tool for AI coding agents, not the React downshift autocomplete library and unrelated to any car transmission.

TL;DR

Per Anthropic's docs, the subagent model in Claude Code comes from the per-call parameter first, then its frontmatter, then CLAUDE_CODE_SUBAGENT_MODEL, then the main conversation's model. Those settings choose one model for a whole agent, so they cannot tell a rename from an architecture review.

The order Claude Code resolves the subagent model

This is the order in the sub-agents docs on 2026-10-19.

PrioritySourceNote
1The model parameter Claude passes when it starts the subagentChosen per call
2The model field in the subagent definitioninherit selects the main conversation's model
3CLAUDE_CODE_SUBAGENT_MODELAn alias or a full model id
4The main conversation's modelThe fallback

The order changed in v2.1.251. Before that, the environment variable came first and overrode both the per-call parameter and the frontmatter. Older guides still describe that order.

In practice, the setting closest to the call wins. What Claude passes for one call beats the agent file, and the agent file beats a session-wide variable. The main model is the last resort.

Frontmatter: inherit, alias or full id

The model field accepts the aliases sonnet, opus, haiku and fable, a full model id such as claude-opus-5-5, or inherit. Anthropic's cost page suggests model: haiku for simple subagent tasks.

---
name: log-reader
description: Reads logs and reports errors
model: haiku
---

CLAUDE_CODE_SUBAGENT_MODEL and the FORCE flag

The environment variable sets one model for every subagent that nothing else assigns. Since v2.1.257, adding CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1 applies it to every subagent and overrides definitions and per-call choices. While FORCE is on, Claude cannot pass a model.

{
  "env": {
    "CLAUDE_CODE_SUBAGENT_MODEL": "haiku",
    "CLAUDE_CODE_SUBAGENT_MODEL_FORCE": "1"
  }
}

Built-in agents: Explore, Plan, general-purpose

  • Explore is read-only. Its model is the main conversation's model, with exceptions when the main model is Fable. To run it cheaper, define a subagent named Explore with model: haiku. Setting CLAUDE_CODE_SUBAGENT_MODEL alone does not change it.
  • Plan is read-only and inherits the main model unless the environment variable with FORCE overrides it.
  • General-purpose uses CLAUDE_CODE_SUBAGENT_MODEL if set and nothing else assigns a model. Otherwise it uses the main model.

Effort is separate from model

A subagent definition can set effort to low, medium, high, xhigh or max, and the available levels depend on the model. From v2.1.292, Claude can also pass an effort per call. The CLAUDE_CODE_EFFORT_LEVEL environment variable overrides both.

Why a subagent may still run on the parent's model

  • Nothing assigns a model, so rule 4 applies.
  • CLAUDE_CODE_SUBAGENT_MODEL_FORCE is on, or the variable is set without the model you expected.
  • The built-in Explore agent follows its own listed rule, not the environment variable.

People also report fallbacks that these rules do not explain. Issue #43869 says all mechanisms resolve to the parent model, and issue #100082 reports frontmatter model ignored, with 1,149 of 1,371 subagents on the parent's Opus. Both were open on 2026-10-19. They are user reports, and I make no claim about their cause.

Static choice versus per-task choice

Frontmatter and the environment variable are static: one answer for an agent or a whole session. A rename and an architecture review that go through the same agent get the same model. A PreToolUse hook can set the per-call model instead, so it can differ per task. Downshift does this on Claude Code, and in one session it was observed to take effect on two spawns.

Two limits. Downshift treats a pinned model as an explicit choice and leaves it alone, so it only routes subagents whose model is not pinned. And with FORCE on, Anthropic says Claude cannot pass a model, so I expect a rewrite not to win there. I have not tested that.

Check what actually ran

/tasks shows each subagent's model and any effort level (v2.1.242 and later). Downshift's downshift try "<task>" previews its decision before a spawn, and downshift session --tree lists the subagents of a session with their cost on Claude Code.

If the model shown is not the one you expected, walk the order from the top and stop at the first rule that applies. That rule is in charge.

Honest status

Verified on Claude Code only. Codex and Cursor are functional, OpenCode is beta. The ~12% figure is a list-price estimate from one operator's controlled run on mechanical delegated tasks (checks passed 12/12 in both arms); on natural complex tasks nothing is attributable yet.

Frequently asked questions

Does model: haiku in frontmatter beat CLAUDE_CODE_SUBAGENT_MODEL?

Since v2.1.251, yes, unless CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1 is set. Before that version the environment variable won.

Will Downshift override a model I pinned in an agent file?

No. A pinned model is an explicit choice, and model: inherit behaves like no model. Omit the field if you want per-task routing.

Why does my subagent still run on Opus?

Check, in order: the model field, the environment variable and FORCE, and whether the agent is a built-in such as Explore. If all are clear and it still follows the parent, issue #43869 shows you are not alone.
